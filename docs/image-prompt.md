# Image Prompt — Diagram Style System

The standing style brief for every image made for this site.
It comes from the Gemini Gem that generates the images, kept here so Gemini, Antigravity and Claude all work from the same words.
Edit this file when the Gem changes, and keep the Gem in step with it.

## How to use it

- Paste this whole brief into the Gem, or into any image tool, ahead of the description of the image.
- The brief fixes the look. The request names the subject: which diagram, what it shows, where the boundary or gate sits.
- Output goes in `static/` or beside the article in `src/content/`, never the repository root.

## Diagram Style System

Mode: personal.

The diagram should feel:
- severe
- restrained
- architectural
- judgmental or indifferent
- structurally composed

It should not feel:
- generic SaaS
- friendly UX
- UML textbook
- bright startup infographic
- DevRel cartoon

## Core Rules

- White backgrounds are out. Use dark field compositions.
- Boundaries, gates, and crossings are the main subject.
- One dominant path per diagram.
- Labels are sparse, declarative, and poster-like.
- Shapes are hard-edged and structural.
- Red is reserved for breach, danger, or unauthorized crossing.
- "Allowed" should look narrow and deliberate.
- "Ambient authority" should look too open, too permissive, or structurally careless.

## Mode: Personal

Purpose:
- exploratory thinking
- personal brand diagrams
- lithographic robot / conceptual content
- X, Instagram, and YouTube

Palette:
- Dominant: `#0C080F`
- Structure: `#1E1A3A`
- Primary accent: `#5C4B8A`
- Signal accent: `#3FA7A3`
- Tension accent: `#A6B82E`, up to 5%
- Undertone: `#3A2F5C`, up to 10%

Behavior:
- more poetic
- more exploratory
- can feel mythic or philosophical
- use cyan and acid tension sparingly as conceptual signals
- diagrams can lean more symbolic than literal

Best for:
- abstract authority concepts
- "what went wrong" explanations
- pattern maps
- creator-brand educational visuals

## Typography Direction

- condensed, sharp, poster-like headings
- minimal body text
- all labels should feel intentional and carved in
- avoid soft, rounded, "product UI" type choices

## Diagram Families

Keep only 3 core visual types:
1. Authority Map for architecture.
2. Authority Flow for sequence.
3. Authority Boundary for checkpoint / trust-boundary visuals.
