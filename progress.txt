## Learnings
- AIDD upstream is ESM, name 'aidd', bin 'aidd' → bin/aidd.js
- AIDD's "execute" is a markdown prompt in ai/commands/execute.md; the actual agent spawner is lib/agent-cli/runner.js
- The fork wraps lib/agent-cli/runner.js via runExecute to enforce the one-ticket boundary
- Commander v11 subcommand option parsing: parent options consume flags before subcommand sees them; use unique flag names
- The dry-run pattern requires short-circuiting BEFORE any state mutation, not after
- Atomic file writes (temp + rename) are essential for state and log integrity
- Playwright should be lazy-imported so projects without it get a clear error rather than a hard import failure

## Next time
- The first upstream merge rehearsal will likely surface conflicts in lib/agent-cli/runner.js, lib/cli-core.js, package.json, and ai/skills/aidd-task-creator/SKILL.md. Document them in FORK.md after the rehearsal.
- The npm postinstall "playwright install --with-deps chromium" needs network access; may want to make it a separate npm install step in CI.
- The gate status exit code 2 conflicts with Commander's own error exits; consider standardizing on a small set of exit codes (0 ok, 1 not yet unblocked, 2 invalid usage, 3 internal error).
